
# 피싱사이트 분석 프로그램 - 통합 정리

세 의견 모두 핵심 구조는 동일하고, 표현과 디테일에 차이가 있어 **공통 부분 → 항목별 차이점 → 통합 제안** 순서로 정리했습니다

---

## 1. 정의

- 사용자가 URL 입력 → **실제 사이트 접속 없이** URL 문자열 자체만 분석
- 판정 결과: **정상 / 의심 / 피싱 가능성 높음** 3단계 분류
- 결과로 **위험 점수 + 판정 근거**를 리포트 형태로 제공
- 학습 데이터: **UCI PHIUSIIL Phishing URL Dataset**

---

## 2. 피싱사이트 유무 분석 항목

- URL 길이
- 특수문자·숫자 비율
- 서브도메인 개수 (과도한 서브도메인)
- IP 주소 형태 도메인 여부
- Punycode 사용 여부
- 의심 키워드 포함 여부
- path·query 길이

---

## 3. 세 의견의 차이점

| 구분 | 의견 1 | 의견 2 | 의견 3 |
|---|---|---|---|
| 분류 모델 | 로지스틱 회귀 고정 | RF / XGBoost / LR 중 선택 | 로지스틱 회귀 고정 |
| 리포트 생성 방식 | 규칙 기반 리포트 (점수+근거) | LLM이 자연어 리포트 생성 | LLM이 자연어 리포트 생성 |
| LLM의 역할 | 없음 | 판정 결과 해석 + 대응 방안 제시 | **판정에는 관여하지 않고 해석·설명만 전담** (역할 분리 명시) |
| 대화형 기능 | 없음 | 없음 | 사용자 추가 질문에 대화형 설명 제공 |
| 특징 추출 도구 명시 | 없음 | urllib.parse, 정규식 명시 | 없음 |

---

## 4. 통합 제안 (겹치는 내용 제거 후 정리본)

### ① 데이터 & 특징 추출
- UCI PHIUSIIL 데이터셋 사용
- Python `urllib.parse`, 정규식으로 위 7가지 특징 추출 및 전처리

### ② 분류 모델
- 1차: 로지스틱 회귀로 베이스라인 구축
- 필요시 Random Forest / XGBoost와 성능 비교 (선택 사항으로 확장)
- 출력: 피싱 확률(위험 점수)

### ③ 리포트 생성 (2단계 구조로 역할 분리)
- ML 모델은 **판정(점수 산출)만** 담당
- LLM은 판정 결과와 주요 특징을 입력받아 **왜 의심스러운지, 어떤 조치를 권장하는지**를 자연어로 설명
- 사용자가 추가 질문 시 **대화형으로 부연 설명** 제공

### ④ 기술 스택
- Python, pandas, scikit-learn (특징 추출·분류)
- LLM API (해석·설명·대응 가이드 생성, 대화형 Q&A)

---

## 5. 결론

**의견 3**이 의견 1과 2의 장점을 가장 잘 통합하면서 "ML = 판정, LLM = 설명"이라는 역할 분리와 대화형 기능까지 포함한 가장 완성도 높은 버전입니다.

이를 베이스로 하되, **의견 2의 모델 비교(RF/XGBoost) 아이디어**를 옵션으로 추가하면 겹침 없이 세 의견의 장점을 모두 살릴 수 있습니다.
